# 2. Computer Architecture & Program Execution

## Basics in Computer Architecture

## What is a Computer?
- Computer
  - 데이터를 저장, 검색, 처리할 수 있는 프로그래밍 가능한 전자 장치
  - 컴퓨터의 형태들
    - Data Center
    - Server Rack
    - Desktop
    - System-on-Chip 부품들

## Stored-Program Computer
- 컴퓨터는 저장 장치 주로 메모리에 저장된 프로그램을 실행

## Computer System Abstraction
- Computer Architecture
  - 프로그래머에게 보이며 프로그램의 논리적 실행에 영향을 미치는 속성들
  - 계층 구조
    - Software
    - Computer Architecture ISA
    - Hardware

## Attributes in Computer Architecture
- Data Type 인코딩 및 표현 방식
- Memory Model
- Program Visible Processor State 범용 레지스터, PC, 프로세서 상태
- Instruction Set 명령어 및 포맷, Addressing modes, 데이터 구조
- System Model 상태, Privilege, 인터럽트, I/O
- External Interfaces I/O, 관리 인터페이스

## A Typical Computer Organization
- CPU 내부
  - Control unit
  - Arithmetic logical unit ALU
  - Registers
- Main memory
- I/O devices Disk, Printer 등
- Bus

## Computer Structure
- CPU 메모리에 있는 데이터를 처리
- Memory
  - RAM 실행 중인 프로그램을 임시 저장 Volatile memory
  - ROM 컴퓨터 동작에 필수적인 프로그램과 정보를 포함 Non-volatile memory
- Peripherals Serial ports, Parallel port, Keyboard, Monitor 등

## Bus
- CPU를 메모리 및 주변 장치와 연결하는 전선 라인
- Data bus
  - CPU 내부 및 외부로 정보를 전달하는 데 사용되는 데이터 라인
  - 일반적인 크기 8bit, 16bit, 32bit, 64bit
  - Bidirectional 양방향 데이터 이동

## Address bus
- CPU에 연결된 장치 및 메모리를 식별하는 데 사용
- Unidirectional CPU에 의해서만 값 변경
- 각 장치별 할당 주소 범위 예시
  - 8비트 주소 라인 64byte RAM, 32byte ROM, 16개 I/O 포트
  - RAM 주소 0 – 63
  - ROM 주소 64 – 95
  - I/O 포트 주소 96 – 112
- $n$개 주소 라인의 총 주소 범위는 $2^n$ byte
  - 8비트 주소 라인 $2^8 = 256$ byte
  - 32비트 주소 라인 $2^{32} = 4\text{GB}$ 주소 범위

## Control bus
- CPU가 장치들의 동작을 제어하기 위해 보내는 제어 정보
- 3가지 버스의 조합에 따른 동작 예시
  - CPU가 메모리 위치 32에서 데이터 읽는 과정
    1. CPU가 주소 버스 값을 32로 설정
    2. CPU가 제어 버스를 사용해 메모리를 읽기 모드로 설정
    3. CPU가 데이터 버스를 통해 데이터 읽음

## Inside CPU
- ALU
  - 산술 기능 add, subtract 등
  - 논리 기능 and, or, not 등
- Registers
  - 정보를 임시로 저장
  - 메모리나 장치에서 읽은 데이터는 레지스터에 먼저 저장 후 처리
  - 계산 결과는 레지스터에 저장 후 메모리로 전송
  - 연산 예시 3 + 5
    1. 3을 레지스터 A에 로드, 5를 레지스터 B에 로드
    2. ALU가 3 + 5 계산
    3. 결과 8을 레지스터 A에 저장
  - 일반적인 크기 8bit, 16bit, 32bit, 64bit
- Instruction
  - CPU 특정 동작에 대응하는 특수 바이너리 패턴
  - 예시 `1011 0000 (B0H)` 레지스터 A로 데이터 이동
  - 예시 `0000 0100 (04H)` 레지스터 A에 특정 값 더하기
  - 프로그램은 일련의 명령어 순서이며 메모리에 저장됨
- Instruction Register IR
  - 메모리에서 프로그램을 한 번에 한 명령어씩 읽어 임시 저장
- Program Counter PC
  - 인출할 명령어의 메모리 주소를 가리킴
- Instruction Decoder
  - 명령어 의미를 해석하여 실행 유도

## RISC and CISC
- CISC Complex Instruction Set Computer
  - 다수의 명령어
  - 가변 길이 명령어 포맷
  - 특수 작업 수행 복잡한 명령어 존재
  - 코드 크기가 작을 수 있음
  - 아키텍처 복잡도 증가
- RISC Reduced Instruction Set Computer
  - 상대적으로 적은 수의 명령어
  - 고정 길이, 쉽게 디코딩되는 포맷
  - 코드 크기가 커질 수 있음
  - 아키텍처 복잡도 감소
  - 트렌디한 아키텍처

## Processor Architectures
- Von-Neumann 명령어와 데이터가 동일한 메모리에 저장됨
- Harvard 데이터와 명령어가 분리된 메모리에 저장됨

## Instruction Execution Process
1. Fetch instruction 다음 명령어를 IR로 읽어옴. PC가 명령어 주소를 지님.
2. Decode instruction op-code를 디코딩하고 필요한 피연산자를 가져와 ALU로 라우팅
3. Execute instruction 실행을 위한 ALU 제어 신호 생성

## CPU Pipelining
- 명령어 처리율을 높여 성능 향상
- 하드웨어 자원을 완전히 활용 가능

## Cache Memory
- CPU에 직접 연결되어 메인 메모리와 상호작용하는 빠른 메모리
- 프로세서는 주소 지정된 워드가 캐시에 있는지 확인
- 캐시 미스 발생 시 해당 워드를 포함하는 메모리 블록을 캐시로 이동

## Effectiveness of Caching
- $1/1,000,000,000\text{초} = 1\text{ns}$
- 일반 명령어 1개 실행 $0.5\text{ ns}$
- L1 캐시 메모리 인출 $5\text{ ns}$
- 분기 예측 실패 $7\text{ ns}$
- L2 캐시 메모리 인출 $25\text{ ns}$
- Mutex lock unlock $100\text{ ns}$
- 메인 메모리 인출 $20,000\text{ ns}$
- 1Gbps 네트워크 2KB 전송 $250,000\text{ ns}$
- 메모리 1MB 순차 읽기 $8,000,000\text{ ns}$
- 새로운 디스크 위치 인출 seek $20,000,000\text{ ns}$
- 디스크 1MB 순차 읽기 $150\text{ ms} = 150,000,000\text{ ns}$

## Cache Architecture Variations
- Unified Instruction and Data Cache
  - 하나의 캐시 메모리에 명령어와 데이터가 함께 저장
- Separate Data and Instruction Caches
  - L1-I 캐시와 L1-D 캐시가 물리적으로 분리
- Hybrid Caches
  - L1 레벨은 분리형, 하위 L2 레벨은 통합형 구조

## I/O Interface
- Memory-mapped I/O
  - 메모리와 I/O가 동일한 주소 공간 공유
  - 일반 메모리 명령어 사용해 I/O 접근
- Port-mapped I/O
  - 메모리와 I/O가 별도의 주소 공간 보유
  - 전용 명령어 사용해 I/O 접근

## Interrupts
- 프로세서가 장치 이벤트에 반응하는 메커니즘
- 장치에서 인터럽트 요청 신호 IRQ 발생 시 현재 작업을 중단하고 인터럽트 핸들러 ISR 호출
- 명령어 주기 내 확인 과정
  - 명령어 실행 완료 시 인터럽트 발생 여부 확인
  - 제어권을 핸들러로 이전하여 처리 후 기존 프로그램으로 복귀
  - 프로그램 어느 지점에서나 발생 가능하며 상태 정보 저장

## Program Execution

## Levels of Program Code
- High-level language
  - 문제 영역에 가까운 추상화 수준
  - 생산성 및 이식성 제공
- Assembly language
  - 명령어의 텍스트 표현
- Machine Code
  - 하드웨어 이진 표현 방식
  - 인코딩된 명령어 및 데이터

## Program Execution Trace
- 프로세서의 일련의 Execution Step
  - Fetch Instruction PC 주소의 기계어 읽기
  - Decode Instruction 명령어 해석 및 연산자 확인
  - Execute Instruction 레지스터 및 ALU를 통한 데이터 연산 수행
  - PC 증가 및 다음 명령어 실행 진행

## How are programs stored in memory?
- 프로그램 구성 요소
  - Code 명령어 메모리 Flash 저장
  - Data 데이터 메모리 SRAM DRAM 저장
- 메모리 로딩 과정 상세
  - Step 1 코드 섹션과 데이터 섹션의 메모리 분리 배치
  - Step 2 초기화 데이터 및 BSS 섹션 매핑
  - Step 3 Stack 및 Heap 공간을 포함한 런타임 메모리 배치
- Binary File Loading
  - Flashing View 컴파일된 바이너리가 플래시에 기록되는 관점
  - Execution View 부팅 후 런타임 데이터가 SRAM으로 복사되는 관점
